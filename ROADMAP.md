# ShadowCrawler Roadmap

This roadmap outlines the planned direction for ShadowCrawler after the initial public release.  
The focus is on stability, maintainability, and high‑quality improvements driven by real user needs.

ShadowCrawler follows a **pragmatic development philosophy**:  
features are added when they provide clear value, improve developer experience, or are sponsored.

---

## 🎯 Core Priorities

### **1. Stability and Bug Fixes**
- Improve engine reliability  
- Fix edge‑case issues in spiders, extractors, and auth  
- Strengthen error handling and diagnostics  
- Ensure consistent behavior across platforms  

### **2. Developer Experience Improvements**
- Better CLI messages and debug output  
- More helpful exceptions  
- Cleaner scaffolding templates  
- Optional quality‑of‑life utilities  

### **3. Documentation Enhancements**
- More examples  
- More spider templates  
- Clearer guides for auth, browser mode, and extractors  

---

## 🧩 Potential Future Enhancements  
These features may be added depending on demand, community interest, or sponsorship.

- Plugin system  
- Distributed crawling  
- Dashboard / Web UI  
- Cloud runner  
- Auto‑throttling  
- Advanced scheduling  
- Spider marketplace / premium spiders  

---

## 💼 Sponsored Development  
ShadowCrawler supports **sponsored features and custom spiders**.

If your organization needs:

- A custom spider  
- A specialized extractor  
- A private auth handler  
- A tailored crawling workflow  
- A feature not currently planned  

You can sponsor development to prioritize it.

---

## 🧭 Philosophy Going Forward

ShadowCrawler will continue to evolve with a focus on:

- Quality over quantity  
- Maintainability over complexity  
- Real‑world needs over speculative features  

The goal is to keep the framework **lean, powerful, and sustainable**.
